Info

Informacion Del Mod

Prepara una actualizacion en el servidor, revisala y publicala. Los jugadores la reciben dentro de Minecraft.

Que hace

Agrega, actualiza y quita archivos del cliente sin que los jugadores reinstalen todo el modpack. Ven la version, el changelog, los archivos cambiados y el progreso de descarga.

Preparar Revisar Publicar

Requisitos

Minecraft 1.20.1 con Forge 47+, instalado en el servidor y en cada cliente. La administracion requiere permisos de OP.

1.20.1 Forge 47+ OP

Archivos gestionados

Mod Updater puede gestionar mods, config, resourcepacks y shaderpacks. Solo toca lo que administra; el resto de tu instalacion queda intacto.

mods/ config/ resourcepacks/ shaderpacks/

Instalacion

Se requiere en el servidor y en cada cliente.

Servidor

  1. Instala Forge para Minecraft 1.20.1.
  2. Coloca el JAR de Mod Updater dentro de la carpeta mods del servidor.
  3. Inicia el servidor una vez para que Mod Updater cree sus archivos y carpetas.
  4. Detén el servidor antes de preparar tu primera actualizacion.

Cliente

  1. Instala Forge para Minecraft 1.20.1.
  2. Coloca el mismo JAR de Mod Updater dentro de la carpeta mods del cliente.
  3. Inicia Minecraft y unite al servidor.

Nota: Mod Updater no actualiza su propio JAR activo. No coloques el actualizador dentro de staging.

Publicar Una Version

Flujo del administrador para preparar, revisar y publicar cambios.

01 · Preparar

Pon en mod-updater/staging/ los archivos que quieres en la proxima version, con la misma estructura de carpetas. Agregar, reemplazar o quitar un archivo de staging define el cambio.

02 · Revisar

Ejecuta /modupdater preview para ver archivos nuevos, actualizados y eliminados, problemas de dependencias y si el servidor necesita reiniciarse.

03 · Publicar

Desde el menu de administracion o con /modupdater publish, indica version, si es obligatoria y el changelog. Sin cambios reales, no se crea una publicacion vacia.

Antes de publicar, /modupdater dependencies revisa los metadatos de los mods locales y busca dependencias obligatorias faltantes; nunca las descarga de Internet. Si ya la tenes local, /modupdater dependencies copy la copia al pack.

Si cambian mods del servidor, los OP reciben un recordatorio para reiniciarlo. Ese aviso operativo nunca se muestra a jugadores normales.

Que Ocurre Para El Jugador

La obligatoriedad decide si puede posponer la version. El contenido decide si Minecraft necesita reiniciarse.

● Al dia

Sin pendientes

El icono indica que no hay nada pendiente y la version instalada coincide con la publicacion.

● Opcional

Actualizacion opcional

El jugador ve su version, la disponible, el changelog y los archivos agregados, actualizados y eliminados, y presiona Descargar Actualizacion cuando quiera.

● Obligatoria

Actualizacion obligatoria

Se abre automaticamente. Hasta instalarla, el servidor puede impedir que el jugador participe con normalidad para evitar problemas de compatibilidad.

Los archivos se transfieren en partes, varios pueden descargarse a la vez y las descargas interrumpidas se pueden retomar. Cada archivo se verifica contra su tamaño y hash SHA-256 esperados antes de instalarse.

Commands

Comandos

Comandos de nivel OP 2 para administrar y publicar versiones.

/modupdater menu

Abre Actualizacion y, para administradores, la pestaña Administrar.

/modupdater preview

Analiza staging y muestra cambios y dependencias sin publicar.

/modupdater publish <version> <true|false> [notas]

Publica una version obligatoria (true) u opcional (false).

/modupdater dependencies

Comprueba las dependencias obligatorias disponibles y faltantes.

/modupdater dependencies copy

Copia al pack las dependencias compatibles que ya existen localmente.

/modupdater reset confirm

Reinicia el estado de publicacion a version 0. Usalo unicamente para comenzar una instalacion nueva.

Quitar Archivos Publicados

Mod Updater solo elimina archivos que pertenecen a su estado de publicacion.

  1. Quitalo de mod-updater/staging.
  2. Ejecuta /modupdater preview.
  3. Comprueba que aparezca como eliminado.
  4. Publica una nueva version.
  5. Los jugadores descargan y aplican la actualizacion.

Si el archivo esta en uso, Minecraft va a necesitar reiniciarse para poder eliminarlo.

Lados De Los Mods

CLIENT

Se envia a los jugadores pero no se instala en la carpeta mods del servidor.

SERVER

Instalado en el servidor pero no se envia a los jugadores.

BOTH

Usado tanto por el servidor como por los jugadores.

Mod Updater intenta detectar el lado correcto usando los metadatos y dependencias del mod. Los casos especiales se configuran en mod-sides.json, y las dependencias exclusivamente de cliente ya conocidas pueden colocarse en mod-updater/client-mods/. Si una actualizacion cambia mods SERVER o BOTH, los operadores reciben un aviso para reiniciar; los jugadores normales no lo ven.

Diseñado Para No Dejar Instalaciones A Medias

Algunos cambios se aplican sin reiniciar Minecraft. Si la actualizacion cambia mods activos, reemplaza archivos bloqueados o elimina archivos en uso, se ofrece la opcion de Reiniciar Minecraft.

Firmado

Los manifiestos de actualizacion estan firmados criptograficamente.

SHA-256

Cada archivo descargado se verifica contra su tamaño y hash SHA-256 esperados.

Rollback

Si la instalacion falla, se restauran automaticamente los archivos anteriores.

  1. Se preparan los archivos descargados.
  2. Minecraft se cierra.
  3. El instalador comprueba la actualizacion.
  4. Se respaldan los archivos existentes.
  5. Se instalan los archivos nuevos.
  6. Si algo falla, se restauran los archivos anteriores.

Una vez instalada correctamente, la nueva version queda guardada como instalada y no se vuelve a pedir a menos que los archivos gestionados dejen de coincidir. Una actualizacion opcional igual puede requerir reinicio: opcional solo significa que el jugador elige cuando instalarla.
